## Work flow Manual

> 1~3 은 모든 프로젝트에 적용한다.
> 4~5 는 웹·앱 프로젝트 중 배포가 있는 경우에만 적용한다.
> 다수의 프로젝트는 3(log 저장)에서 종료된다.

### 1. project start

* **about** : Perry 가 초반 세션창에 전달한 프로젝트 ID 바탕으로 작업 진행
* **appendix** :
  * 해당 ID 는 구글드라이브를 제외한 채널에 다 있음
    * 문서 및 파일이 없는 프로젝트 경우 구글드라이브에 ID 없음
  * Perry 가 ID 를 전달하지 않았을 때, AI Agent 는 리마인드 함

### 2. 작업 중

* **about** : ID 를 기준으로 각 채널에서 자료를 찾아 작업
* **appendix** :
  * Notion = 프로젝트 HUB / GitHub = 코드·마크다운 / Google Drive = 문서·자료
  * Perry 가 링크로 지정한 문서 밖은 임의로 검색하지 않고 물어봄
  * 자료가 어느 채널에도 없으면 지어내지 않고 없다고 말함

### 3. log 저장

* **about** : 프로젝트 진행 상황 기록. 인수인계서 역할
* **appendix** :
  * Perry 가 로그 기록을 요청했을 때만 기록함. 자동으로 남기지 않음
  * 위치 : `psw95master/{ID}/@log/`
  * 파일명 : `{ID}_@log_{YYMMDD}.md`
  * 같은 날짜 파일이 있으면 덮어쓰지 않고 이어붙임
  * 저장 후 문서 링크를 보고에 반드시 포함함
  * 배포가 없는 프로젝트는 여기서 종료됨

### 4. 배포 ※웹·앱 한정

* **about** : 테스트 서버에서 검수 후 라이브 서버로 반영
* **appendix** :
  * 테스트 링크로 검수 → 승인 후 라이브 반영
  * 반영 후 실제 페이지가 떴는지 확인까지 하고 보고함
    * 빌드 성공과 배포 성공은 별개임. 빌드만 되고 배포가 죽는 경우가 있음
  * 테스트 서버와 실서버는 프로젝트마다 지정함. 각 프로젝트 README 에서 확인
    * PH-A-7 (260820 기준) : 테스트 서버 = GitHub / 실서버 = 260821 구축 예정

### 5. project close

* **about** : 프로젝트 종료 시 AI Agent 가 Perry 에게 마감 항목을 리마인드함
* **appendix** :
  * Perry 가 종료 의사를 밝히거나, 작업이 끝난 것으로 보이면 AI Agent 가 먼저 물음
  * 리마인드 항목 (확정된 것만. 프로젝트를 닫을 때마다 실제로 한 일을 여기 추가함)
    * log 저장했는지
    * 라이브 반영 후 실제 페이지 확인했는지 (배포가 있는 프로젝트)
    * ※ 이하 작업하면서 채움
  * AI Agent 가 임의로 종료 처리하지 않음. 리마인드까지만 하고 판단은 Perry 가 함
