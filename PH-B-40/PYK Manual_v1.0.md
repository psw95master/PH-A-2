## Member & R&R

| 이름 | 무엇 | 어디 |
| --- | --- | --- |
| 페리 | 김민우 | 사람 |
| 세리 | claude code | `macbook_pro_19y` |
| 팹 | claude code | `macbook_air_26y` |

* **about** : Perry 와 함께 일하는 구성원
* **appendix** :
  * **이름은 기기로 정해진다.** 창구(CLI·슬랙)로 판단하지 않음
    * `macbook_pro_19y` 에서 도는 세션 = 세리
    * `macbook_air_26y` 에서 도는 세션 = 팹
    * 자칭하기 전에 "이 세션이 어느 기기에서 도는가"를 먼저 확인함
  * **세리와 팹은 메모리를 공유하지 않음**
    * 각자 자기 기기에만 메모리를 둠. 옆 기기가 무슨 작업을 했는지 알 수 없음
    * 옆 기기에 물어볼 방법이 없으므로, 모르는 것은 Perry 에게 물음
    * 같은 프로젝트를 두 에이전트가 동시에 만지면 작업이 충돌함

## Response Rule

* **about** : 응답·작업 기준과 디자인 원칙. 이 문서가 아니라 별도 정본을 따름
* **appendix** :
  * **STYLE.md** — 항상 적용. 응답·작업 기준
    * [`PH-B-24. Memory of comm/STYLE.md`](https://github.com/psw95master/PH-A-9/blob/main/PH-B-24.%20Memory%20of%20comm/STYLE.md)
  * **DESIGN.md** — 설계·프로토타입 작업일 때만 적용
    * [`PH-B-24. Memory of comm/DESIGN.md`](https://github.com/psw95master/PH-A-9/blob/main/PH-B-24.%20Memory%20of%20comm/DESIGN.md)
  * 정본은 깃허브 `psw95master/PH-A-9` 한 벌이며, 베리티·팹·세리가 공유함
    * 260820 공개 전환됨. 권한 없이 열림
    * 공개 전환하면서 보안상 `PH-B-25. Memory of PAB` / `PH-B-27. Memory of Cerryde` 는 삭제됨. 남은 것은 `PH-B-24. Memory of comm` 뿐임
  * **이 매뉴얼에 두 문서의 내용을 옮겨 적지 않는다.** 두 벌이 되면 반드시 어긋남
  * 세션 시작 시 한 번 읽고, 이후 답변·산출물을 내기 전마다 기준으로 삼음

## Keyword Manual

### ID

* **about** : 폴더명에 부여되는 ID 값
* **appendix** :
  * 형식 : `(코드)-(시리얼)-(넘버)`
    * 예시 : `PH-A-4`
    * `A` : Project (프로젝트)
    * `B` : Files (파일)
    * `C` : Note (메모)
  * 노션 내 로우데이터 기능으로 ID 가 제작되며, 1번 생성 시 절대 변경 안 됨
  * ID 내 숫자는 계층을 의미하는 숫자가 아님
  * 노션 데이터베이스 기준으로 프로젝트, 파일, 노트에만 부여되어 있음
  * 해당 ID 바탕으로 자료를 찾음
  * Perry 가 세션에서 ID 전달하지 않았을 때, AI Agent 는 리마인드 함

### log

* **about** : 프로젝트 진행 상황을 기록하는 도구. 인수인계서와 같은 역할
* **appendix** :
  * Perry 가 로그 기록 요청 시, 프로젝트 ID 와 일치하는 깃허브 레포지토리 내 `@log` 폴더에 기록함
  * 파일명은 `{프로젝트 ID}_@log_{작성일}` 로 함
    * 예 : `PH-A-7_@log_260818.md`
    * `@` 가 폴더명과 파일명 양쪽에 붙음
  * 같은 날짜 파일이 이미 있으면 덮어쓰지 않고 이어붙임

### Deploy

* **about** : 배포 관련 서버와 링크 구분
* **appendix** :
  * **테스트 서버** : 라이브 서버 배포 전 개발코드가 있는 곳. 깃허브에 저장됨
  * **라이브 서버** : 실제 웹에서 노출되고 있는 페이지 코드가 있는 곳. 테스트 서버에서 배포한 코드와 동일함
  * **테스트 링크** : 라이브 서버 배포 전 검수용 url. 깃허브 url 로 되어 있으며, 첫 진입 시 패스워드 팝업창 노출
  * **라이브 링크** : 실제 웹에서 노출되고 있는 url. 패스워드 팝업창이 없음

## Work flow Manual

> 1~3 은 모든 프로젝트에 적용한다.
> 4~5 는 웹·앱 프로젝트 중 배포가 있는 경우에만 적용한다.
> 다수의 프로젝트는 3(log 저장)에서 종료된다.

### 1. project start

* **about** : Perry 가 초반 세션창에 전달한 프로젝트 ID 바탕으로 작업 진행
* **appendix** :
  * 해당 ID 는 구글드라이브를 제외한 채널에 다 있음
    * 문서 및 파일이 없는 프로젝트 경우 구글드라이브에 ID 없음
  * Perry 가 ID 를 전달하지 않았을 때, AI Agent 는 리마인드 함

### 2. 작업 중

* **about** : ID 를 기준으로 각 채널에서 자료를 찾아 작업
* **appendix** :
  * Notion = 프로젝트 HUB / GitHub = 코드·마크다운 / Google Drive = 문서·자료
  * Perry 가 링크로 지정한 문서 밖은 임의로 검색하지 않고 물어봄
  * 자료가 어느 채널에도 없으면 지어내지 않고 없다고 말함

### 3. log 저장

* **about** : 프로젝트 진행 상황 기록. 인수인계서 역할
* **appendix** :
  * Perry 가 로그 기록을 요청했을 때만 기록함. 자동으로 남기지 않음
  * 위치 : `psw95master/{ID}/@log/`
  * 파일명 : `{ID}_@log_{YYMMDD}.md`
  * 같은 날짜 파일이 있으면 덮어쓰지 않고 이어붙임
  * 저장 후 문서 링크를 보고에 반드시 포함함
  * 배포가 없는 프로젝트는 여기서 종료됨

### 4. 배포 ※웹·앱 한정

* **about** : 테스트 서버에서 검수 후 라이브 서버로 반영
* **appendix** :
  * 테스트 링크로 검수 → 승인 후 라이브 반영
  * 반영 후 실제 페이지가 떴는지 확인까지 하고 보고함
    * 빌드 성공과 배포 성공은 별개임. 빌드만 되고 배포가 죽는 경우가 있음
  * 테스트 서버와 실서버는 프로젝트마다 지정함. 각 프로젝트 README 에서 확인
    * PH-A-7 (260820 기준) : 테스트 서버 = GitHub / 실서버 = 260821 구축 예정

### 5. project close

* **about** : 프로젝트 종료 시 AI Agent 가 Perry 에게 마감 항목을 리마인드함
* **appendix** :
  * Perry 가 종료 의사를 밝히거나, 작업이 끝난 것으로 보이면 AI Agent 가 먼저 물음
  * 리마인드 항목 (확정된 것만. 프로젝트를 닫을 때마다 실제로 한 일을 여기 추가함)
    * log 저장했는지
    * 라이브 반영 후 실제 페이지 확인했는지 (배포가 있는 프로젝트)
    * ※ 이하 작업하면서 채움
  * AI Agent 가 임의로 종료 처리하지 않음. 리마인드까지만 하고 판단은 Perry 가 함
