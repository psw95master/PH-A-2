# PH-A-2_260820 — 공통(PYK) 매뉴얼 착수 · 로그 규칙 개정

공통 매뉴얼의 목차 6개를 확정하고 그중 `Work flow Menual` 절을 마감했다. 작업 도중 매뉴얼 초안과 실제 운용 규칙이 어긋난 것을 발견해, 로그 저장 규칙(위치·파일명·ID 체계)을 새 기준으로 통일했다.

## 배경 (Why)

- 목적은 **AI Agent 와 PYK 신규 입사자가 Perry 와 작업할 때 참조할 행동 기준**을 한 벌로 만드는 것.
- Perry 가 1차 목차 4개(`Account` / `Channel` / `Keyword Menual` / `Work flow Menual`)와 상세 내용을 전달.
- 검토 결과 두 가지 문제가 나왔다.
  1. 초안에 적힌 로그 규칙이 실제로 돌고 있는 규칙과 어긋남 — 매뉴얼이 정본이 되려면 먼저 맞춰야 함
  2. AI Agent 가 읽는 문서인데 "나는 누구이고 어디까지가 내 일인가"를 알려주는 절이 없음

### 2. 충돌 3건 확정 — 초안 vs 기존 스킬

`AIS-1_save-log` 스킬(`~/.claude/skills/AIS-1_save-log/SKILL.md`)이 낡아 있었다.

| 항목 | 기존 스킬 | 확정 |
| --- | --- | --- |
| 저장 위치 | 구글 드라이브 `00. log` 폴더 | **깃허브 `psw95master/{ID}/@log/`** |
| 파일명 | `{ID}_log_{YYMMDD}.md` | **`{ID}_@log_{YYMMDD}.md`** |
| ID 코드 | `psw` / `pab` | **`PH` 하나** (psw·pab 은 테스트용 구값, 전량 삭제) |
| ID 시리얼 | `a`=brand / `b`=plan / `c`=project | **`A`=Project / `B`=Files / `C`=Note** |

> ⚠️ Perry 가 준 지시 예시(`{ID}_log_{YYMMDD}` → `{ID}_log_{YYMMDD}`)가 좌우 동일해 `@` 위치를 특정할 수 없었다. 추측하지 않고 되물어 `{ID}_@log_{YYMMDD}` 로 확정.

**같이 삭제한 것** — 기존 스킬의 `슬랙 채널명 = brand DB 의 ID = 드라이브 폴더명` 규칙. `psw`/`pab` 체계 전제라 함께 걷어냈다. 새 체계의 슬랙 채널명 규칙은 아직 없다.

**현물 확인 결과** — 스킬 문서만 드라이브 시절에 멈춰 있었고, 실제 로그는 이미 깃허브(`psw95master/PH-A-7/log/`)에 쌓이고 있었다. 문서와 현물이 따로 논 상태였다.

### 3. PH-A-7 현물 개명

새 규칙을 기존 로그 6개에 소급 적용했다.

- `log/` → `@log/`
- `PH-A-7_log_260805.md` ~ `260818.md` → `PH-A-7_@log_*.md`
- `README.md` · `@log/README.md` 의 경로 참조 갱신
- 로그 본문 안의 상호 참조 위키링크 `[[PH-A-7_log_*]]` → `[[PH-A-7_@log_*]]` (5개 파일, 17곳)

마지막 항목은 개명만 하고 놔두면 문서 간 링크가 전부 끊기는 자리였다.

### 4. 🔴 팹과 동시 작업 충돌

푸시가 거부되어 보니 **팹이 26맥에서 같은 레포에 커밋 3개를 이미 올려둔 상태**였다.

```
b51ed03 [팹] 로그 폴더명을 @log 로 확정
2c19e45 [팹] 로그 폴더명을 #log 로 변경
0ff4448 [팹] log 폴더명을 @log 로 변경
```

팹은 **폴더명만** 바꾸고 파일명은 `_log_` 그대로 뒀다. 세리는 폴더+파일명을 모두 바꿔, rebase 시 `rename/rename` 충돌이 7개 파일에서 발생했다.

**해결** — `git reset --hard` 로 로컬을 버리고 다시 하려 했으나 권한 거부. 대신 충돌을 직접 해소했다. 파일 개명은 세리 쪽(`_@log_`)을 채택하고, README 2개는 충돌 마커를 제거하며 새 명명 기준으로 통일.

> ⚠️ 세리와 팹은 메모리를 공유하지 않아 서로가 뭘 하는지 모른다. 같은 레포에 동시에 붙으면 매번 이렇게 된다. 이를 근거로 `1. project start` 에 "한 프로젝트 ID 는 한 에이전트에게만 지시" 규칙을 제안했으나, **Perry 판단으로 기각** — 현재 구조상 한 에이전트만 붙는 것이 정상이고 변수 상황까지 제약할 필요는 없다.

### 5. Work flow Menual 확정

5단계로 잡되 **조건부 구조**로 갔다.

```
1. project start → 2. 작업 중 → 3. log 저장 → [4. 배포] → [5. project close]
```

- 1~3 은 모든 프로젝트 공통. **다수의 프로젝트는 3에서 종료된다.**
- 4~5 는 웹·앱 프로젝트 중 배포가 있는 경우에만.
- `5. project close` 는 내용이 아직 없어 **리마인드 형식**으로 뼈대만 뒀다. AI Agent 가 마감 항목을 묻기만 하고, 종료 판단은 Perry 가 한다. 항목은 프로젝트를 닫을 때마다 실제로 한 일을 추가해 채운다.
